# Глобальная ИИ-обработка выделенного текста (Golosok Fork)

Форк репозитория `Berliner187/Golosok` с добавлением функционала трансформации выделенного текста по горячей клавише через встроенные пресеты и локальную/облачную LLM.

## Архитектура и принцип работы

Функционал встроен как расширение существующей архитектуры Голоска, без создания сторонних процессов и с сохранением основного голосового назначения приложения (диктофон GigaAM):

1. **Глобальный хоткей (⌥ + ⇧ + Space / Option + Shift + Space):**
   - Зарегистрирован в `NativeHotKeyManager` под ID `2` через Carbon `RegisterEventHotKey`.
   - Полностью настраивается в GUI: **Настройки → Управление → «ИИ-обработка выделения»**.
   - Не конфликтует с основным хоткеем диктовки (`⌥ + Space`).

2. **Захват выделенного текста (`AISelectionManager`):**
   - Запоминает целевое приложение (`frontmostApplication` / `PID`).
   - Сначала пробует прочитать текст напрямую через macOS Accessibility API (`kAXSelectedTextAttribute`).
   - Если приложение (например, Electron или браузер) не отдаёт атрибут, делает безопасный fallback через эмуляцию `Cmd+C` (`0x08`) с предварительным сохранением буфера обмена.
   - Если текст не выделен — выводит предупреждение *«Сначала выделите текст»* и не сбивает буфер.

3. **Палитра промптов (`AISelectionToolbarPresenter`):**
   - Использует уже существующий в Голоске плавающий компонент `AISelectionToolbarContent`.
   - Подтягивает список шаблонов из `PromptStore.shared.templates` (как встроенные «Исправить ошибки», «Деловой стиль», «Улучшить стиль» и др., так и пользовательские).
   - Всплывает точно у позиции курсора мыши (`NSEvent.mouseLocation`).
   - **Управление:**
     - Мышь: клик по строке пресета.
     - Клавиатура: клавиши `1`...`9` для мгновенного выбора пресета без движения мыши.
     - Отмена: глобальная клавиша `Esc` или клик в любом месте экрана.

4. **Индикация процесса (`OverlayPanel` + `AudioCapture`):**
   - После выбора промпта окно выбора закрывается, а вверху экрана появляется нативный оверлей Голоска со светящейся фиолетовой анимацией (`RotatingGlowBorder`), иконкой ✨ и статусом *«ИИ-обработка...»*.
   - Целевое приложение остаётся с активным выделением.

5. **Инференс LLM (`AIService`):**
   - Формирует запрос через существующий метод `template.messages(for: text)`.
   - Отправляет запрос в сконфигурированный в Голоске инференс (`AIProviderStore.shared.config`):
     - Локальный `llama-server` (`http://127.0.0.1:8080/v1`) с рекомендованной моделью `Qwen3.5-4B Q4_K_M`.
     - Или `Ollama` (`http://127.0.0.1:11434/v1`).
     - Или внешние API (OpenAI, Groq, DeepSeek).

6. **Замена выделения (`replaceSelection`):**
   - Очищенный ответ LLM помещается в системный `NSPasteboard`.
   - Активируется целевое приложение (`targetApp.activate`).
   - Через `CGEvent` в PID приложения отправляется `Cmd+V` (`0x09`), заменяя выделенный текст.
   - Оверлей показывает зелёную галочку успеха (`SuccessCheckView`), проигрывается звук успеха (`SoundEffect.playSuccess()`), и оверлей плавно исчезает.

## Измененные и созданные файлы

* `Golosok/AISelectionManager.swift` (новый): координатор всего сценария (Accessibility, Pasteboard, LLM, Cmd+V).
* `Golosok/NativeHotKeyManager.swift`: регистрация второго глобального хоткея по ID, диспетчеризация событий Carbon.
* `Golosok/HotKeySettings.swift`: хранение, перехват и валидация комбинации клавиш для ИИ-трансформации.
* `Golosok/AISelectionToolbar.swift`: глобальное закрытие по `Esc`, поддержка цифр `1`–`9` и отображение бейджей клавиш.
* `Golosok/AudioCapture.swift`: методы управления состоянием `aiStatusText`, старт/финиш/отмена оверлея.
* `Golosok/OverlayPanel.swift`: отображение фиолетовой glow-капсулы при выполнении запроса к LLM.
* `Golosok/SettingsView.swift`: блок настройки хоткея в интерфейсе «УПРАВЛЕНИЕ».
* `Golosok/GolosokApp.swift`: привязка вызова `AISelectionManager.shared.trigger()` к событию нажатия.
